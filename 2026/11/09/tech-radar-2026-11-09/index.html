技術雷達精選｜GitHub Actions 公開專案執行政策變更

AI 協助整理 · 2026-11-09 · 2 分鐘閱讀

12/2 起公開 repository 的 pull_request_target 將預設受限。先盤點觸發事件，再決定是否需要最小範圍例外。

本篇節選自 2026/11/02–11/08 的 Engineering Tech Radar，於 11/13 重新核對官方公告。僅整理一項已確認的重要變更，不代表該週完整技術新聞。

變更重點

GitHub 宣布，自 2026/12/02 起，公開 repository 的 pull_request_target 事件預設遭封鎖，除非適用的 Actions event policy 明確允許。Private、internal repository 與 GitHub Enterprise Server 不在本次適用範圍。

原因是此事件使用 base repository 的執行環境，可存取其 secrets；若執行來自 fork 的不可信程式碼，可能暴露憑證。

時間與準備

官方排定兩次短暫強制測試，換算台灣時間為 11/10、11/17 的 00:00–02:00。截至本篇複核，第一次窗口已過，第二次仍待到來。

建議先搜尋 workflow 的觸發事件，透過 Insights 確認預計遭阻擋的執行。若確實需要保留此事件，應審查不可信輸入及 secret 權限，並將允許政策限縮至必要 workflow，而非一律放行。

適用判斷： 沒有使用此事件的專案，不應僅因這份公告而更動流程。
